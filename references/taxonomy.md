# 核查规范：AI 痕迹的八层判据

> 本文件是**判定标准**。规则 ID 与代码一一对应（`references/rule-index.md` 是自动生成的目录）。
> 每条都写清四件事：**判据**（多机器可判）、**反例**（不许报的情况）、**误伤风险**、**怎么修**。

> 改过规则后跑两个测试：`python tests/selftest.py`（黄金样本回归）
> 与 `python tests/word_roundtrip.py`（真 Word 往返，需装 Word）。

---

## 第 0 节：为什么分层，而不是列一堆毛病

「AI 痕迹」不是一个东西，是三种东西混在一起：

| 种类 | 例子 | 谁来做 |
| --- | --- | --- |
| **字符级污染** | 零宽字符、`共 3 个`、半角逗号 | 脚本做，且能证明做完是对的 |
| **格式级残留** | `**加粗**`、字号漂移、Calibri 混入 | 脚本只能**指出**，转换成 Word 原生格式必须人做 |
| **语义级味道** | 「综上所述」「赋能闭环颗粒度」 | 脚本只能**定位**，删改必须人拍板 |

把这三类混在一张清单里，结果是：要么脚本乱改内容，要么人要在 200 条里翻找 5 条真问题。
所以：**分层 → 层号就是自动化边界 → 层号就是处理顺序**。

## 第 I 层 · 不可见字符

看不见，但会污染检索、复制、比对、对齐。**全部自动**。

| 规则 | 判据 | 怎么修 | 反例 |
| --- | --- | --- | --- |
| `I01` | 命中 `U+200B/200C/200D`（零宽）、`U+2060`、`U+FEFF`、`U+00AD`（软连字符）、`U+202A–202E`/`U+2066–2069`（方向控制） | 直接删 | 无。这些字符在正文里没有任何合法用途 |
| `I02` | 命中 `U+00A0`（不换行空格）、`U+2009`/`U+2008`/`U+202F`/`U+2007`（细空格类） | 左右任一侧是中文 → 删；否则 → 换成半角空格 | 在**英文**两侧（`10 kg`）时保留为普通空格，不能删 |
| `I03` | 正文中间出现 `U+3000`（全角空格） | 换半角空格（后续由 S08 决定去留） | **段首**的全角空格不在这里处理 —— 那是"伪缩进"，归 `B04` |

> **为什么算 AI 痕迹**：人用 Word 打字几乎不可能产出零宽字符和不换行空格；
> 它们几乎只能来自「从网页/AI 对话里复制粘贴」。

## 第 S 层 · 空白与间距

这一层是**取向问题**，不是对错问题，所以由 `--preset` 控制。

| preset | 取向 | 适用 |
| --- | --- | --- |
| `word-cn`（默认） | 全角标点；**中英、中数之间不留空格** | 飞书/Word/公文/内部报告 |
| `word-cn-loose` | 只清标点与不可见字符，中英之间空格保留 | 只想清标点时的保守选项 |
| `word-tech` | 中英之间**保留**空格（盘古之白），标点仍按中文规范 | 技术博客/README 类文档 |

| 规则 | 判据 | 反例 / 风险 | 自动 |
| --- | --- | --- | --- |
| `S01` | 汉字与数字之间的空格：`共 3 个` `2026 年` | 数字带单位且单位是英文时（`10 kg`）不归它管 —— 那里是**西文空格**，是规范 | ✅ |
| `S02` | 汉字与拉丁词之间的空格：`使用 Python` | 中英之间加不加空格是**排版取向**，所以默认不自动；要清得显式 `--rules S02` | ⚠️ 默认否 |
| `S03` | 中文标点**外侧**的空格：`完成 ，` `、 后面` | 只清外侧。标点**内侧**不归它管 | ✅ |
| `S04` | 连续 ≥2 个半角空格（非段首） | 有人在页眉用多个空格做假对齐 —— 所以默认不自动 | ⚠️ 默认否 |
| `S05` | 括号内侧填充：`（ 说明 ）`、`( 说明 )` | 全角括号的情况常被 `S03` 先吃掉，没吃掉才归它 | ✅ |
| `S06` | 数字与 `%` `‰` `℃` `°` 之间的空格：`50 %` | 无。百分号前不留空格是硬规范 | ✅ |
| `S07` | 段落收尾的空白（AI 折行最容易在段尾留空格） | 无 | ✅ |
| `S08` | **两个汉字之间的空格**：`共 发现` | 中文里两个汉字之间凭空空格没有合法用途；这是 Markdown 软折行粘进 Word 的典型产物 | ✅ |

> **为什么 `汉字 空格 汉字` 一定是痕迹**：人写中文不会在汉字中间敲空格，
> 而 Markdown 里一个段落被折成多行时，渲染/粘贴会把换行变成空格 —— 于是留下这个。
> 它是**最能直接证明「这份稿子是从 Markdown/AI 输出粘过来的」的单条证据**。

## 第 P 层 · 标点符号

**全部规则都必须看左右邻字符。** 全局替换一定会破坏 `1,000`、`9:30`、`v1.2`、`e.g.`、URL。

| 规则 | 判据 | 反例（不许报） | 自动 |
| --- | --- | --- | --- |
| `P03` | `...`（≥3 个点）、`。。。`、单个 `…` → `……` | 整段是英文时的 `...` 不报 | ✅ |
| `P01` | 半角 `, . ; : ? !` 出现在中文语境 → 转全角 | 小数点 `1.5`、千分位 `1,000`、时间 `9:30`、缩写 `e.g.`、版本 `v1.2`、URL 里的全部半角、**路径里的点（`.github/workflows/`、`os.path`、`run-all.ps1`）** | ✅ |
| `P02` | 直引号 `"` `'` 成对出现在中文语境 → `“”` `‘’` | 只出现奇数个时不报（无法判断配对）；代码/路径里的引号不报 | ⚠️ 默认否 |
| `P04` | **恰好两个**连字符 `--` → `——` | 单个 `-` 是连字符/范围号；`---` 是 Markdown 分隔线（归 `M09`） | ⚠️ 默认否 |
| `P05` | 叠标点 `！！` `？？` `，，` → 单个 | `……` 是规范写法，不在此列（归 `P03`） | ✅ |
| `P06` | 半角括号内**过半是中文** → 外侧换全角 `（…）` | 内层嵌套的英文括号（`A(B)`）保留；被 `\` 转义的括号归 `M11` | ⚠️ 默认否 |
| `P07` | 全角数字 `０-９`、全角字母 `Ａ-ｚ` → 半角 | 无。全角字母数字会让检索、复制、比对全部失配 | ✅ |
| `P08` | `％` → `%`；时间里的全角冒号 `9：30` → `9:30` | 中文语境里的全角冒号是**对的**，只有两侧都是数字时才转 | ⚠️ 默认否 |
| `P09` | 纯数值范围里的 `～` → `-`（`3～5 度`） | 中文语境里的波浪号表示"约"（`100～200 人`）时也可能是有意的 —— 所以默认不自动 | ⚠️ 默认否 |

> **顺序有讲究**：`P03`（省略号）必须排在 `P01`（半角标点）**之前**。
> 否则 `...` 会先被 P01 吃掉一个点变成 `。..`，越清越乱。这就是"规则优先级"存在的理由。

> **点号不是标点。** 路径、文件名、域名、代码标识符里的 `.` 是**名字的一部分**，不是句号。
> 所以这些 token 先被掩码整体保护起来（见 `references/docx-protection.md` 第五节、
> `references/protection-index.md`），P01 根本看不到它们。
> 一条最典型的判据：**`.github/workflows/` 里的点换成 `。` 就废了** —— 而这句话本身
> 在中文里很常见（"放在 `.github/workflows/` 下"），所以这条保护是硬需求。

## 第 M 层 · Markdown 残留（Word 场景的头号 AI 痕迹）

AI 生成的 Markdown 直接粘进 Word，**符号会变成可见的字面文本**。
这一层百分之百是"从 AI 输出粘过来的"证据，只要命中就一定是错的。

| 规则 | 判据（字面形状） | 该改成什么 |
| --- | --- | --- |
| `M01` | `**文字**`、`__文字__` | Word 加粗格式（Ctrl+B），删掉星号 |
| `M02` | `*文字*`、`_文字_` | Word 斜体格式 |
| `M03` | 行首 `#` 到 `######` | Word 标题样式（这才有导航窗格和目录） |
| `M04` | 行首 `- ` `* ` `+ ` `1. ` `1、` | Word 项目符号/自动编号 |
| `M05` | 行内 `` `代码` `` | 等宽字体（Consolas/等线），去掉反引号 |
| `M06` | 行首 ```` ``` ```` 或 `~~~` | 段落底纹 + 等宽字体，或表格框 |
| `M07` | `[文字](http…)` | 正文文字 + Word 超链接 |
| `M08` | `\|---\|` 这类分隔行 | Markdown 表格要重画成 Word 表格 |
| `M09` | 整行的 `---` `***` `___` | 段落边框或分页符 |
| `M10` | 行首 `> ` | Word「引用」样式或缩进段落 |
| `M11` | 转义符残留：`\*` `\_` `\(` `\)` `\#`… | 删掉多余反斜杠。**看掩码**：路径里的 `\.`（如 `C:\Users\x\.pi`）不算转义残留，不报 |
| `M12` | `&nbsp;` `&amp;` `<br>` `<p>` `<div>` | 换成真实字符或删标签 |

> **为什么这一层只建议不自动**：把 `**重点**` 换成加粗不是"删两个星号"，
> 而是**对两个位置做格式操作**（要动 run 的 rPr）。脚本盲改会制造半加粗的碎片，
> 反而更像事故。这一步必须人在 Word 里做，脚本负责把位置精确指出来。

## 第 B 层 · 段落与换行

| 规则 | 判据 | 为什么算痕迹 |
| --- | --- | --- |
| `B01` | 段落内有 `<w:br/>`（Shift+Enter 手动换行） | 人排版用「段落 + 段间距」；AI 文本搬进来常连着软换行 |
| `B02` | 连续 ≥1 个空段落 | 用空行凑间距是 AI 搬运的常态；规范做法是段前/段后间距 |
| `B03` | 连续 ≥5 个段落，每段 ≤25 字 | **一句话一段**是 AI 输出最显眼的排版特征；中文正文通常按意思合并成段 |
| `B04` | 段首用空格或全角空格缩进 | 应该用「段落 → 缩进 → 首行缩进 2 字符」；空格缩进在改字号后就废了 |
| `B05` | 段落 ≥20 字、以**汉字**结尾、没有终结标点 | 折行没接上的残留（`……内容\n另一段` 粘成一行的反面） |
| `B06` | 单段 >300 字 | 不是 AI 独有，但 AI 一次输出长段很常见；只是提示按语义切分 |

`B03` 的阈值（5 段 / 25 字）是经验值：低于它，正常文档（如清单式写法）会误报。

## 第 F 层 · 格式与样式

这一层抓的是「**这份文档是拼出来的**」的证据，不是美丑。

| 规则 | 判据 | 为什么算痕迹 |
| --- | --- | --- |
| `F01` | 正文出现 **>2 种字号**（含只出现一次的字号） | 人写一份文档通常只有 2–3 级字号；多出来的那一个就是"从别处粘来的" |
| `F02` | **同一段内**混用 >1 种字体 | 正常段落整段同字体；段内混排＝拼接 |
| `F03` | 正文出现 Calibri / Times New Roman / Segoe UI / Arial / Helvetica / Consolas | 这是**网页和其他软件**的默认字体。中文文档里出现它们＝从网页粘的 |
| `F04` | 正文出现非黑（`#000000`/auto）的字体颜色 | 正式文档正文宜用自动色 |
| `F05` | **>15% 的字符是加粗** | AI 把"重要"理解成"要加粗"；人类文档加粗量通常 <5%。一片黑体＝没有重点 |
| `F06` | 段落对齐方式混用（justify 与 left 并存） | 同一份文档正文应统一 |
| `F07` | ≥3 个**无样式**段落单独设了段前/段后间距 | 逐段手调间距＝拼装；应统一到样式里 |
| `F08` | 加粗 + 字号 ≥14pt + 短行 + 无 Heading 样式 | 「手工标题」：不能生成目录、导航窗格看不见、改字号会漏 |
| `F09` | 含中文的段落只设了 `w:ascii`/`w:hAnsi`，没设 `w:eastAsia` | 换机器/换 Word 版本中文会变字体 —— 这是"在别的软件里生成的"的指纹 |

## 第 L 层 · 语言层 AI 味

**只报告，只定位，不改写。** 判据是词表 + 句式正则，词表在 `assets/lexicon-zh.txt`，可以直接加词。

| 规则 | 判据 | 为什么算痕迹 |
| --- | --- | --- |
| `L01` | 词表 `filler`：首先/其次/最后、值得注意的是、需要指出的是、不可否认、众所周知 | 这些词删掉句子照样成立 —— 它们只提供"节奏"不提供信息，是 AI 的行文习惯 |
| `L02` | 词表 `summary`：综上所述、总而言之、总的来说、归根结底 | AI 每篇必总结；人写内部文档很少来这么一句 |
| `L03` | 词表 `vague`：赋能、抓手、闭环、生态体系、颗粒度、底座、中台 | 空壳名词：听着像有内容，实际没说给谁加了什么能力 |
| `L04` | 词表 `hollow_adv`：极大地、显著地、充分地、有效地、有力地、至关重要 | 程度不是事实；要么给数字，要么删 |
| `L05` | 词表 `meta`：让我们、接下来我、如上所述、简而言之 | 元话语：文档里不该出现"我要开始写了" |
| `L06` | 正则：`不是…而是…`、`并非…而是…` | 对举句式是 AI 的招牌节奏 |
| `L07` | 正则：`不仅…而且…`、`既…又…` | 递进壳子，删掉结论更直接 |
| `L08` | 词表 `era`：在当今、随着…的不断发展、势在必行、任重道远 | 时代背景开场：AI 的万能开头 |
| `L09` | 正则：`(促进\|推动\|助力\|提升)[^，。]{0,12}的(发展\|提升\|优化)` | 空壳谓语：动作+空宾语 |
| `L10` | **>3 个段落**都出现「A、B、C」三项排比 | 三项排比单次很正常；**密度高**才是 AI 节奏（人写中文自然会在 2 项和 4 项之间变化） |
| `L11` | 破折号 **>6 处/千字** | 破折号是 AI 最爱用的连接方式 |

**`L` 层的正确用法**：不是"把这些词都删掉"，而是**让作者看一眼自己是不是在用这些词躲开具体表达**。
报告里给出的建议（`（删）`／`（改成具体动作）`）是**选项**，不是命令。

## 第 C 层 · 内容层

| 规则 | 判据 | 处置 |
| --- | --- | --- |
| `C01` | `作为(一个)(AI\|人工智能\|语言模型\|大模型)`、`我是(AI\|…)` | ⛔ 整句删除。交付文档里出现这个是事故 |
| `C02` | `希望对你有帮助`、`如需进一步…请`、`随时告诉我`、`我来帮你`、`以上是我为你` | ⛔ 整句删除。这是对话客套，不是文档内容 |
| `C03` | `以上内容仅供参考`、`具体请以…为准`、`如有错误请指正` | ⚠️ 按文档性质决定删或改成正式口径说明 |
| `C04` | 40–160 字 + 含总结词 + **零数字** | ⚠️ 空壳总结段：没有新信息、没有数字，只在复述。建议整段删 |
| `C05` | ≥12 字的同一句在文中出现 ≥2 次 | ⚠️ 重复句（AI 复读） |
| `C06` | `[待补充]`、`【待补充】`、`TODO`、`TBD`、`此处省略`、`XX` | ⛔ 占位符出现在交付文档里是事故 |
| `C07` | `下面我将从…`、`本文将从…`、`接下来我们看…` | 💡 承诺式开头：直接进入内容 |

## 附：这八层里，哪些必须"人眼一拍板"

即使脚本报得再准，下面这些**只有人能做决定**：

1. **M 层全部** —— 转成 Word 原生格式是排版动作。
2. **L/C 层的删减** —— 删掉"综上所述"后面的那一段，等于删掉一个论点，可能删掉真内容。
3. **`F01/F02/F03` 的统一目标** —— 统一到哪个字体、哪个字号，是设计决定。
4. **`B03` 的合并方式** —— 哪几段该合成一段，取决于语义。

脚本的职责边界就是：**把位置指得足够精确，让上面这四件事变成"确认"而不是"找"**。
