# 报告契约

> 三个文件、一套字段。**脚本之间靠它对接**，人靠第一部分读结论。

## 一、`report.md`（人读）

由 `docx_scan.py` 写信到 `<稿件名>.ai-trace/report.md`，固定四段：

```markdown
# AI 痕迹审计报告
（表头）文件 / 扫描时间 / 预设 / 扫描层 / 范围（段落数·字数·部件清单）

## 一、摘要
按层统计的表：层 | 说明 | ⛔硬阻 | ⚠️警告 | 💡建议 | 其中可自动  → 末行合计

## 二、可自动修复清单
一键命令 + 按规则聚合的条数表（规则 | 条数 | 说明）

## 三、明细
按层分组，每条一行：
- <标记> **<规则ID>** `<部件>` §<pid> · <上下文片段>
  - <说明>　→ <若有替换，给出建议文本>

## 结尾声明
只做建议、不改文档；机械层可用 docx_apply 落盘；其余四层必须人工处理。
```

**上下文片段约定**：用 `« »` 框住命中的那几个字符，前后各取 12 字。
不可见字符要在片段里**显式可见**，否则报告读起来是空的：

| 字符 | 报告里的写法 |
| --- | --- |
| `U+200B` 零宽空格 | `«ZWSP»` |
| `U+00A0` 不换行空格 | `«NBSP»` |
| `U+3000` 全角空格 | `«全角空格»` |
| `<w:br/>` 手动换行 | `⏎` |

## 二、`report.json`（机读）

```jsonc
{
  "stats": {
    "file": "绝对路径", "scanned_at": "YYYY-MM-DD HH:MM:SS",
    "preset": "word-cn", "layers": "ISPBMFLC",
    "parts": ["word/document.xml", "word/header1.xml"],
    "paragraphs": 81, "chars": 2083, "words": 643,
    "issues": 164, "auto": 53, "hard": 55, "warn": 77, "sug": 32
  },
  "issues": [ /* Issue[]，按下表排序 */ ]
}
```

### Issue 字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `rule` | str | 规则 ID，如 `S01` |
| `layer` | str | `I S P M B F L C` 之一 |
| `severity` | str | `hard` / `warn` / `sug` |
| `part` | str | zip 部件名，如 `word/document.xml` |
| `pid` | str | 段落号 `p0001`（**每个部件各自从 p0001 开始，所以 part+pid 才是唯一键**） |
| `anchor` | str | 段落开头 20 字，供人快速定位 |
| `start` / `end` | int | 段落内的字符坐标（含哨兵 `\t` `\n`）；段落级问题为 `-1` |
| `orig` | str | 命中的原文片段 |
| `repl` | str | 建议替换文本（空串＝只报告不替换） |
| `note` | str | 人话说明 |
| `auto` | bool | 是否允许被 `docx_apply.py` 自动落盘 |

排序：层顺序（I→S→P→M→B→F→L→C）→ 严重度降序 → 部件 → 段落号 → 字符位置。

**`auto=true` 的充要条件**（四条全满足）：
1. 层是 `I`/`S`/`P`；
2. 规则不在 `NO_AUTO` 名单里（`S02 S04 P02 P04 P06 P08 P09`）；
3. 所属 run 不在域结果里（`in_field_result=false`）；
4. 所属 run 不在修订插入里（`in_insertion=false`）。

## 三、`<输出>.applied.json`（落盘凭证）

`docx_apply.py` 在写盘前生成，是 `docx_guard.py` 做逐字节重放的**唯一输入**。

```jsonc
{
  "source": "原稿绝对路径",
  "preset": "word-cn",
  "note": "只含 I/S/P 三层的字符级替换；每轮坐标相对上一轮结果",
  "applied": [
    { "round": 0, "rule": "S01", "part": "word/document.xml", "pid": "p0003",
      "start": 4, "end": 5, "orig": " ", "repl": "" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `round` | 第几轮定点迭代。**必须按 round 升序重放**，因为第 N 轮的坐标是相对第 N−1 轮结果算的 |
| `orig` | 改之前那段文字，重放时用于**校验坐标没错位**；对不上就判失败 |

为什么不做成"diff 补丁"而做成分轮替换记录：因为一次替换会改变后面所有坐标，
记录"意图"比记录"结果"更容易在重放时自证正确。

## 四、退出码（所有 CLI 共用）

| 码 | 含义 | 谁用 |
| --- | --- | --- |
| `0` | 无命中（scan）／成功（apply、guard） | 可以进下一步 |
| `1` | 只有 💡 建议级命中 | 可交付，但建议看一眼 |
| `2` | 有 ⚠️ 警告级命中 | 交付前应处理 |
| `3` | 有 ⛔ 硬阻命中（scan）／**校验失败（guard）** | 必须处理／必须回滚 |
| `10` | 参数或执行出错（文件不存在、规则名非法…） | 修参数重跑 |

`docx_apply.py` 的退出码：`0` 成功（含"无需改动"）｜`3` 校验失败已丢弃｜`10` 参数错。
**它不会返回 1/2** —— 它要么干净地写完，要么什么都不写。
