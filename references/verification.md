# 最后的校验规则（G1–G7）

> 这一页是**验收门**。`docx_apply.py` 落盘前会自动跑一遍；不过就整个丢弃。
> 想手动验证别人改过的文件，直接调 `docx_guard.py`。

## 一、为什么需要七道，而不是"跑一遍没报错就行"

只有一道检查是**证明**（G3），只有一道检查是**约束计划本身**（G4/G5），
其余是防"文件坏了打不开"和"改了没改干净"这类工程问题。

| # | 检查 | 怎么查 | 失败处置 |
| --- | --- | --- | --- |
| **G1** | 包结构不变 | zip 条目名与顺序完全相同 | 回滚 |
| **G2** | 非文本部件逐字节不变 | 逐个 `bytes` 比对（样式、关系表、图片、`[Content_Types].xml`…） | 回滚 |
| **G3** | **逐字节重放证明** | 把 `.applied.json` 里的替换在**原稿**上按轮次重放，结果必须与清理后**逐字节相同** | 回滚 |
| **G4** | **语义 token 集合不变** | 数字（含 `%`）、URL、拉丁词、代码标识符，前后必须是**同一个集合** | 回滚 |
| **G5** | 段落/run 骨架不变 | 段落数与每段 span 数一一对应；段落样式与 `pPr` 原文相同 | 回滚 |
| **G6** | XML 可解析 | 每个 `.xml`/`.rels` 都能被 XML 解析器读出（否则 Word 会弹「需要修复」） | 回滚 |
| **G7** | **幂等** | 对清理后的文档再跑一遍 I/S/P，必须 **0 处可自动命中** | 回滚 |

## 二、G3 与 G4 为什么必须同时有

它们管的是两件不同的事，缺一个都留下一个漏洞：

- **G3 管"有没有超范围改动"**：证明「除了这次计划要做的 N 处替换，文档里其它字节一个都没变」。
  它防的是：脚本顺手改了别的地方、坐标错位改串了位置、`xml:space` 忘了加。
- **G4 管"计划本身对不对"**：如果某条规则错了（例如把 `3 个` 里的 `3` 也吃了），
  G3 依然会通过 —— 因为"计划"和"执行"是一致的，错的是计划。
  这时 G4 抓它：token 集合少了 `num:3`。

> **一句话**：G3 证明**说到的都做到了**，G4/G5 证明**没说到的没被碰**，
> G7 证明**做到位了**。三个加起来才是"这份文档只被我们按规矩改过"。

### G3 判失败时怎么读错误

| 报错 | 含义 |
| --- | --- |
| `原文是 ' '，记录里是 '　'` | 坐标错位（第 N 轮的坐标是相对第 N−1 轮算的，轮次顺序乱了） |
| `未预期的差异：word/document.xml` | 替换之外还有字节变了 —— 十有八九是忘了处理 `xml:space` |
| `找不到所属 run` | 段落/run 结构与记录不一致（可能被别的工具同时改过） |

### G4 判失败时怎么读错误

| 报错 | 含义 | 典型原因 |
| --- | --- | --- |
| `少了 num:3` | 有规则吃掉了数字 | 正则写宽了（`[^，]{0,5}` 把数字吃了） |
| `多了 lat:abc` | 有规则**造出**了拉丁字母 | 罕见；通常是替换文本里塞了不该塞的东西 |
| `少了 url:http…` | 碰了链接 | 某条规则越过了 URL 掩码 |

> 注意：G4 会先做 **NFKC 归一化**。因为本 skill 的规则**故意**要把全角数字/字母/`％` 转半角，
> 那是我们要的结果，不能在护栏里被当成"改了事实"。

## 三、回滚与诚实

```
临时文件写入 → G1..G7 → 全过？ → 是：备份原稿为 .bak，替换
                        → 否：删除临时文件，原稿分毫未动，退出码 3 并逐条打印失败项
```

**禁止**为了"让校验通过"而放宽校验、跳过校验、或手改 `.applied.json`。
如果 G3/G4 抓到问题，正确动作是：找出是哪条规则、写进 `tests/make_sample.py` 当样本、修规则、重跑自检。

校验失败时的对用户口径：

> 校验未通过，改动已丢弃，原文件未被动过。原因是 <具体哪一项><具体内容>。
> 我不会绕过这道检查 —— 绕过它等于放弃"只改了该改的地方"这个保证。

## 四、自检（改过本 skill 之后必跑）

```bash
python tests/selftest.py
```

| 项 | 验什么 |
| --- | --- |
| T1 | 脏样本能生成；审计报硬阻（退出码 3）；**每条规则都有样本命中**（加了规则没加样本 → 失败） |
| T2 | scan → apply → guard 全链路退出码为 0 |
| T3 | 11 组关键替换逐字比对（跨 run 删空格这类核心能力必须逐字对） |
| T4 | 清理后文档能被 **python-docx**（第三方独立解析器）打开 |
| T5 | 清理后机械层零残留 |
| T6 | 非文本部件逐字节未变；文本部件的 XML 骨架（挖掉 `<w:t>` 内容后）未变 |
| T7 | 第二次 apply 报「无需改动」（真幂等） |

另有一个**真 Word 往返验证**（需要本机装了 Word）：

```bash
python tests/word_roundtrip.py
```

它用 Microsoft Word 自己生成一份真 `.docx`（十余个部件、真样式表与关系表），
跑完整链路后**再用 Word 把清理后的文件读回来**，比对读回的字符。
这是「Word 打得开、读得对」的唯一可靠证据 —— 手工拼的最小 docx 证明不了这一点。

**T1 的覆盖率门是这套东西能长期活下去的关键**：它把"加了一条规则但没人验证它到底会不会命中"
变成一次构建失败。

## 五、不变量清单（改代码时不许破）

1. 只改 `<w:t>` 的文本内容，除 `xml:space="preserve"` 外不改任何属性。
2. 任何替换都不许跨越 `\t` / `\n` 哨兵（`<w:tab/>`、`<w:br/>`、`<w:cr/>`）。
3. 任何替换都不许落在掩码区间内（URL、小数、版本号、千分位、文件名、代码标识符、`10 kg` 这类量）。
4. `M/B/F/L/C` 五层的 `Issue.auto` 恒为 `false`。
5. 定点迭代必须收敛（最多 8 轮），出现往复状态立即中止。
6. 落盘路径必须经过 `verify()`；没有旁路。
