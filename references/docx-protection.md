# 保护区：哪些字节绝对不能碰

> 这一页是**安全边界的权威说明**。任何新增规则、任何新脚本，都必须先读它。

## 为什么需要"保护区"这个概念

`.docx` 是一个 zip 包，正文在 `word/document.xml` 里，而那段 XML 同时装着：

- 你看到的文字（`<w:t>`）
- 排版规则（段落属性 `w:pPr`、字符属性 `w:rPr`）
- 样式引用、编号引用、超链接关系、书签、批注锚点、域代码、修订痕迹
- 图片、图表、公式的**替代文本**

一个正则替换或一次「读 XML → 改 → 重新序列化」，很容易顺手改掉其中几样。
有些改动立刻可见（版式乱了），有些**在 Word 下次打开时才炸**（弹「发现无法读取的内容，是否修复」）。

所以本 skill 的原则是：

> **只允许改 `<w:t>` 元素的文本内容**（必要时给它加 `xml:space="preserve"`）。
> 其他一切字节逐字节保持原样 —— 这一点由校验器 G3 用「重放后逐字节比对」证明，不靠自觉。

## 一、部件级保护区（整个 zip 条目不许变）

| 路径 | 为什么不能动 |
| --- | --- |
| `word/styles.xml` | 样式定义。动它等于改全文版式 |
| `word/numbering.xml` | 编号与项目符号定义 |
| `word/settings.xml` | 文档级设置（含"打开时更新域"等行为） |
| `word/fontTable.xml`、`word/theme/*.xml` | 字体表与主题配色 |
| `word/webSettings.xml` | 网页视图设置 |
| `[Content_Types].xml` | 包内容类型声明。动了 Word 直接拒绝打开 |
| `_rels/*.rels`、`word/_rels/*.rels` | 关系表（超链接目标、图片引用）。**URL 在这里，不在正文里** |
| `docProps/*.xml` | 文档属性（标题/作者）。可另用 `--include-props` 纳入扫描范围 |
| `word/media/*` | 图片原文件。一个像素都不许动 |
| `customXml/*`、`word/embeddings/*` | 自定义 XML 与嵌入对象 |
| `word/comments.xml` | 批注正文 —— **那是审阅者的话，不是作者的话**。默认不扫 |
| `word/document.xml.orig` 等历史备份部件 | 只能原样保留 |

**默认扫描范围**（只有这些部件的 `<w:t>` 会被读，且只有机械层会写）：
`word/document.xml`、`word/header*.xml`、`word/footer*.xml`、`word/footnotes.xml`、`word/endnotes.xml`。

文本框内容在 `document.xml` 内部的 `<w:txbxContent>` 里 —— **属于正文，要扫**（它在独立的 `<w:p>` 里，是独立段落）。

## 二、元素级保护：这些 `<w:t>` 不参与清洗

| 元素 / 位置 | 处置 | 原因 |
| --- | --- | --- |
| `<w:instrText>…</w:instrText>` | 完全不读 | 这是域代码（`PAGE`、`TOC \o "1-3"`）。改了域就废了 |
| `<w:delText>`、`<w:del>` 内部 | 完全不读 | 修订删除掉的文字，不显示也不能改 |
| `<w:ins>` 内的 `<w:t>` | **读但不自动改**（标记 `in_insertion`） | 是别人审阅时插入的内容，动它等于替他改稿 |
| 域结果（`fldChar type="separate"` 到 `end` 之间） | **读但不自动改**（标记 `in_field_result`） | 目录项、页码会随"更新域"重新生成，改了等于白改 |
| `<m:oMath>` 里的 `<m:t>` | 天然不读 | 公式文本不是 `<w:t>`，正则也匹配不到 |
| `<w:drawing>` / `<w:pict>` 里的**图片数据** | 不动 | 只穿过它去读 `<w:txbxContent>` 里的文本框段落 |
| `<w:bookmarkStart/End>`、`<w:commentRangeStart/End>`、`<w:proofErr>` | 不删不挪 | 删掉会破坏书签和批注锚点 |
| `<w:pPr>`、`<w:rPr>`、`<w:tblPr>`、`<w:trPr>`、`<w:tcPr>`、`<w:sectPr>` | 只读不写 | 属性是版式，读它是为了报 F 层问题 |

## 三、属性级保护：只能加，不能改

唯一被允许的**非文本**改动是：当一个 `<w:t>` 的内容改完之后**开头或结尾变成了空格**，
而它原本没有 `xml:space="preserve"`，就给它加上这个属性 —— 否则 Word 打开时会**默默吃掉那个空格**，
清理结果和报告对不上。

不允许的：改 `w:val`、改 `w:rsid`、改 `xml:lang`、调整属性顺序、改自闭合形式。

## 四、为什么不用解析器重新序列化整个文档

`xml.etree.ElementTree` 或 `lxml` 读进来再写回去，会做这些事：

- 把命名空间前缀重写成 `ns0:`、`ns1:`（除非逐个注册）
- 丢掉 `standalone="yes"`
- 改变自闭合标签的写法（`<w:b/>` ↔ `<w:b></w:b>`）
- 重新排列属性顺序
- 丢掉注释和处理指令

Word 大多能容忍，但**"大多"不够**。而且一旦重新序列化，
「除了我要改的地方，文档没变」这句话就**没法证明了**。

本 skill 选择：**正则在 XML 字节流上定位 `<w:t>` 的边界，只替换边界内部的字节**。
代价是要自己处理转义和 `xml:space`；收益是校验器能给出逐字节的证明。

## 五、文本级保护区（掩码）：哪些**字符序列**不许动

上面四节讲的是「哪些字节不许动」。还有另一半：**同一段文字里，有些 token 的点号和标点
是语义的一部分**，按中文排版规则去改就废了。

```
.github/workflows/        ← 把 `.` 改成 `。` → `。github/workflows/`
C:\Users\Administrator\   ← 同样，而且路径里的空格也不能并
os.path.join              ← 同样
python docx_scan.py --all ← `--` 被当成破折号改成 `——`
`code span`               ← 里面是代码，一个字符都不许动
```

所以规则引擎在动手之前先扫一遍**掩码**：落在掩码区间里的字符，I/S/P 三层**既不修改也不报告**。
规则在 `scripts/protect.py`，家族清单（自动生成）在 `references/protection-index.md`，
目前 **24 个家族**，分五类：

| 类别 | 家族 | 典型受害者 |
| --- | --- | --- |
| 网络地址 | URL、www、邮箱、域名/主机 | `https://github.com/a/b`、`a@b.com` |
| 文件路径 | Windows、UNC、POSIX、相对/家目录、含斜杠 token | `.github/workflows/`、`C:\Users\x\`、`~/.pi/agent`、`和/或` |
| 点号名 | 点开头的名字、带扩展名文件名 | `.gitignore`、`os.path`、`run-all.ps1` |
| 代码与命令 | 反引号代码段、命令行参数、环境变量、标识符、编号、配置行键 | `` `x = 1` ``、`--all`、`%USERPROFILE%`、`JIRA-1234`、`key:` |
| 数字 | 小数/版本、千分位、时间、日期、带单位数值 | `v0.1.0`、`1,234`、`9:30`、`2026-10-13`、`10 kg` |

### 三条必须遵守的规矩

1. **掩码不能挡住该做的修复。** 例如 `%` 不能进单位掩码（否则 `50 %` → `50%` 永远修不了）；
   时间掩码只匹配半角冒号（否则 `9：30` → `9:30` 修不了）；
   命令行参数掩码要求 `--` 前面是分隔符且不能是连字符（否则 `A--B` 的 P04 命中没了）。
2. **掩码不能吞掉紧跟路径的中文正文。** 所以 `放在C:\temp下` 只保护 `C:\temp`，
   结尾那个中文 run 不算进掩码 —— 否则那句正文里的问题会静默漏报。
3. **掩码不影响 M/B/F/L/C 五层。** 代码段里的 `` `x` `` 依然会被 `M05` 指出来；
   掩码只管机械层「改不改」。

这三条都有反向测试守着（`tests/selftest.py` 的 T8，26 个正向 + 10 个反向用例）。

## 六、新增规则前的检查清单

新规则想动一个位置之前，问四句：

1. 这个位置属于上面哪一类保护区？落在哪个掩码家族里？
2. 我的替换会不会跨越 `<w:tab/>`、`<w:br/>`（脚本里有哨兵拦截）？
3. 我的替换会不会吃掉数字、URL、代码标识符？（`tokens()` 集合必须不变）
4. 这条规则如果错了，最坏会怎样？如果答案不是"多删一个空格"，那它就不该进机械层。
5. **我是该加一条掩码，还是加一条规则？** 如果是「这个 token 不该被任何规则碰」，加掩码
   （`scripts/protect.py`），并在 T8 的两个列表里各补一个用例；如果是「这个 token 该被改成别的」，
   才加规则。
