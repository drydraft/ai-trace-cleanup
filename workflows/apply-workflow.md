# 流程 B：清掉机械层（会写文件，所以规矩最多）

> 只有 **I / S / P** 三层能落盘。M/B/F/L/C 五层永远只出建议 —— 见 `references/taxonomy.md`。

## 执行前提（三条，缺一不可）

1. **已经跑过 `audit-workflow.md`**，用户看过报告并知道要改什么。
2. 用户**明确要求清掉机械层**（不是"你自己看着办"）。
3. 原稿有备份可用，或者用户接受脚本自动生成 `.bak`。

## Execution Protocol

1. **顺序锁**：Phase 0→4 串行，不许把 dry-run 和落盘合并成一步。
2. **状态回声**：每阶段开头输出 `[Phase X] <名称>`。
3. **不许静默跳过**：跳过任何一步都要写原因。
4. **不许编造**：改动条数、备份路径、校验结论，全部照抄命令输出。

---

## Phase 0：划定规则白名单

**动作**：决定这次只应用哪些规则。

- 默认：全部 `auto=true` 的规则（`I01 I02 I03 S01 S03 S05 S06 S07 S08 P01 P03 P05 P07`）。
- 用户只想清最刺眼的（例如只要标点）：`--rules P01,P03,P05,P07`
- 想排除某几条：`--exclude S08`
- **`NO_AUTO` 名单里的规则（`S02 S04 P02 P04 P06 P08 P09`）想用必须单列**
  —— 脚本会拒绝把它们放进"全部自动"，因为误伤风险高：

  ```bash
  python scripts/docx_apply.py "稿件.docx" --rules P02,P08 --out "稿件.clean.docx"
  ```

**后置**：能一句话说出"这次会动哪些字符、不会动哪些"。

---

## Phase 1：dry-run 预览（绝不加 `--apply`）

**动作**：

```bash
python <skill_dir>/scripts/docx_apply.py "<稿件>" --out "<稿件>.clean.docx"
```

**读输出**：

- `待替换 N 处，共 M 轮：S01×27、S03×5、…` —— M 轮是**定点迭代**轮数。>1 是正常的
  （例如 `P07` 把全角数字转半角后，`S01` 才能删掉它前面的空格）。
- 逐条预览是 `规则 部件 §段落号 原文 → 新文`。
- 结束时提示「加 --apply 落盘」。

**这一阶段必须把预览给用户看**，尤其是：
- 有 `orig` 是数字附近的替换（确认没吃到数字）；
- 有整段变空的（确认不是误删）。

**后置**：替换条数与"会不会改到不该改的地方"都已确认。

---

## Phase 2：落盘

**动作**：

```bash
python <skill_dir>/scripts/docx_apply.py "<稿件>" --apply
# 想输出到新文件（不动原稿）：
python <skill_dir>/scripts/docx_apply.py "<稿件>" --apply --out "<稿件>.clean.docx"
```

**脚本会做的事（按顺序）**：

1. 在内存里迭代到定点，得到全部替换；
2. 写入临时文件 `<输出>.tmp-ai-trace`；
3. 写出 `<输出>.applied.json`（逐条替换凭证，含轮次）；
4. **调 `docx_guard.verify()` 跑 G1–G7**；
5. 全过 → 备份原稿为 `.bak`（仅当输出＝原文件）→ 把临时文件改名到位；
   任一失败 → 删除临时文件，**原稿分毫未动**，退出码 3。

**后置**：命令返回 0，并打印了七项校验结果。

---

## Phase 3：校验门（已经自动跑过，这里是人工复核）

**动作**：把 Phase 2 输出的七行校验逐条念给用户，重点两条：

| 项 | 该说什么 |
| --- | --- |
| G3 | 「把 N 处替换在原稿上重放，结果与你手里的文件**逐字节相同** —— 这证明除了这 N 处，文档里什么都没变」 |
| G4 | 「数字、URL、代码标识符的集合前后完全一致 —— 这证明没有改到事实」 |

想独立复核（例如文件被别的工具动过）：

```bash
python <skill_dir>/scripts/docx_guard.py "<原稿>" "<清理后>" --applied "<清理后>.applied.json"
```

**后置**：七项全 ✅。有一项 ❌ 就必须走回滚。

---

## Phase 4：交付与交底

**动作**：按这个固定口径汇报：

```
✅ 已写入 <路径>，共替换 N 处（<规则×n 列表>）
   原稿备份：<路径>.bak
   替换清单：<路径>.applied.json
   校验：G1 包结构 ✅｜G2 保护区 ✅｜G3 逐字节重放 ✅｜G4 语义 token ✅
         G5 段落骨架 ✅｜G6 XML 可解析 ✅｜G7 幂等 ✅
⚠️ 这次没动、但报告里有的：
   · M 层 <n> 条（Markdown 残留，要你在 Word 里转成原生格式）
   · F 层 <n> 条（字体/字号/加粗率，要你统一到样式）
   · L/C 层 <n> 条（措辞与内容，纯建议）
```

最后一句必须是：**"清洗后仍然是同一篇文，只是毛刺没了 —— 建议你打开看一遍再发。"**

**后置**：用户知道改了什么、没改什么、备份在哪。

---

## 回滚（校验失败时）

```bash
# 输出到新文件的情况：原稿没被动，直接删掉临时产物即可
Remove-Item "<输出>.tmp-ai-trace","<输出>.applied.json" -ErrorAction SilentlyContinue

# 覆盖写的情况：.bak 就是回滚点
Copy-Item "<稿件>.bak" "<稿件>" -Force
```

对用户的口径：**「校验未通过，改动已丢弃，原文件未被动过。原因：<哪一项><具体内容>。」**
然后修规则 → 补样本 → 重跑 `tests/selftest.py` → 再来一遍。**不许放宽校验。**

## 绝对禁止

| 禁止 | 原因 |
| --- | --- |
| 手工编辑 `.applied.json` 让 G3 通过 | 那等于伪造"我只改了这些"的证明 |
| 跳过 `-—apply` 直接改文件（例如自己写脚本动 XML） | 绕过校验门就是放弃全部保证 |
| 把 M/B/F/L/C 五层也自动落盘 | 那会改版式和语义，超出"去痕"范围 |
| 覆盖原稿却不留 `.bak` | 出问题时无法回滚 |
| 在用户没看过 dry-run 预览的情况下落盘 | 用户必须有机会在改之前喊停 |
