# 流程 A：审计一份 Word 稿（只读，不改文件）

> **本流程只读。** 它产出报告，不产出修改。要清机械层请走 `apply-workflow.md`。

## Execution Protocol（先读，适用于全流程）

1. **顺序锁**：Phase 0→4 严格串行。上一个阶段的后置条件没满足，不许进下一个。
2. **状态回声**：每阶段开头输出一行 `[Phase X] <名称> — 前置：PASS/FAIL`。
3. **不许静默跳过**：确实要跳过（例如用户明确说"不用看页眉"），必须写明跳过原因。
4. **不许编造**：报告里的每个数字都必须来自命令输出。没跑过的命令不许说"已扫描"。

---

## Phase 0：认领输入与范围（先问，别猜）

**前置**：拿到了 `.docx` 路径。
**动作**：

1. 确认文件存在、是 `.docx`。是 `.doc` 就先让用户另存为 `.docx`（本 skill 不解析老二进制格式）。
2. **必须确认的三件事**（一次问完）：
   - **preset**：`word-cn`（默认，全角标点＋中英不留空格）／`word-cn-loose`（保守）／`word-tech`（中英保留空格）；
   - **范围**：要不要扫页眉页脚（默认要）？要不要连批注一起扫（默认不要）？
   - **深度**：只清机械层（`--layers ISP`），还是完整体检（`--all`，含 Markdown 残留与语言层）？
     —— 完整体检命中数会多一个量级，要提前说清楚。
3. 如果用户只是说"帮我看看有没有 AI 味"，**默认走完整体检**，并说明会报哪些层。

**后置**：preset／范围／深度三项都有明确答案（用户说"你定"就按默认，并**显式写出**所用取值）。

---

## Phase 1：机械层（I / S / P）

**动作**：

```bash
python <skill_dir>/scripts/docx_scan.py "<稿件>" --layers ISP --out "<稿件所在目录>"
```

**读结果**时注意三件事：

1. `auto` 计数 = 可自动修复的条数。这个数**不是**最终要改的数，只是"最有把握的一批"。
2. 标着 `默认自动落盘 = 否` 的规则（`S02 S04 P02 P04 P06 P08 P09`）会出现在报告里，
   但**不会**被自动应用 —— 要在结论里单独点出来让用户决定。
3. 跨 run 的命中（`共 3 个` 这种）看上下文片段里的 `« »` 是否框住了那个空格本身。

**后置**：能说出 `⛔/⚠️/💡` 三个数字，以及"其中 N 处可自动修复"。

---

## Phase 2：结构层（M / B）

**动作**：`--all`（若 Phase 0 选的是完整体检），然后**先看 M 层**。

- **M 层是 Word 场景的头号问题**，而且每一项都是"从 Markdown/AI 输出粘过来"的铁证。
  只要 M 层非空，就在结论里排在最前面。
- B 层的 `B03`（一句话一段）、`B02`（空段落凑间距）是排版痕迹，属于"要人动手合并/改样式"的活。

**后置**：能列出 M 层命中了几类（`**加粗**` / `##` / 列表 / 链接 / 分隔行 / 转义 / HTML 实体），
以及 B 层的 `B03`、`B02` 各自出现在哪些段落。

---

## Phase 3：格式层与语言层（F / L / C）

**动作**：看 `F01–F09` 与 `L*` / `C*`。

**这一阶段的输出是"给人看的问题清单"，不是"要改的清单"。**

- F 层讲的是「这份文档是拼出来的」：字号漂移、Calibri 混入宋体、加粗率、手工标题。
  这类问题的修法是**统一到样式**，必须人来定"统一到哪个"。
- L 层讲的是行文习惯。**复述时必须说清这是"建议"**，不能说"我帮你把这些词删了"。
- C 层的 `C01/C02/C06` 是硬阻（自指、客套、占位符），要明确说出来。

**后置**：能分别说出 F／L／C 三层的代表性命中，且**没有把建议说成已完成的动作**。

---

## Phase 4：出结论（说实话）

**动作**：按下面这个顺序复述，**所有数字照抄命令输出，不许估**。

```
1. 一句话结论：硬阻 N 条、警告 N 条、建议 N 条；其中 M 处可以自动清掉。
2. 最该先处理的三件事（按严重度 + 是否可自动）：
   · <规则ID> <人话名字> — 出现在 <部件>§<段落号>，<原片段> → <建议>
3. 机械层：给一条可直接执行的 apply 命令，并说明它会做什么、不会做什么。
4. 必须人做的那部分：明确列出 M 层与 F 层（这两层脚本绝不代劳）。
5. 报告路径：<稿件>.ai-trace/report.md（人读）与 report.json（机读）。
```

**后置**：用户能明确回答"接下来点哪条命令"。

---

## 反模式（这几件事不许做）

| 不许 | 因为 |
| --- | --- |
| 不跑命令就凭印象说"看起来挺干净的" | 报告里每个数字都要有出处 |
| 把 L 层的"建议删"说成"已删除" | 那是改写，本 skill 不做 |
| 直接开始 apply 而不先出审计报告 | 用户有权先看清要改什么 |
| 报出几百条 💡 建议就算了事 | 抓大放小：先硬阻、再警告，建议只给最典型的几条 |
| 改了稿子才告诉用户 | 落盘必须显式确认 |
